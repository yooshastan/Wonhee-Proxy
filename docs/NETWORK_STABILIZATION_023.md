## Evidence and release boundaries
Record per-test PASS/FAIL/SKIPPED, build/commit, selected scope, network type and redacted observations. Avoid credentials, endpoints and DNS query payloads in public logs. CI success is not device acceptance. A failed tunnel/resolver must not cause silent direct Internet fallback for protected scope. Do not call the app leak-proof; crash/handoff/lockdown, exact-owned root cleanup and broader device coverage are separate Product C/F/G/I release gates. See #89 and #41. Do not advance to a signed public beta until these are resolved or unsupported features are clearly excluded.

## 0.25.1 — DNS isolation preview
Uses 0.25.0 configuration-persistence baseline (dde11d202daef6fa1542bed25042ae9c137d0938, code 162); no downgrade or new package. 0.24.0 user packet/log audit supported Exit B isolation and encrypted DNS through global Exit A, with two reported Android system IPsec packets and local mDNS outside the tunnel. This does not prove whole-device lockdown.
Protection now offers Global (existing default), Follow app/DNS rules with an explicitly selected shared resolver exit for unattributed queries, and Strict (deny unattributed queries). Android may conceal original app behind system resolver; the socket owner is not always original requesting app. Strict may break ordinary Android hostname resolution; no automatic fallback. DNS destination-port overrides take precedence for attributable requests. Split modes allocate independent per-exit encrypted socket pools, positive caches, coalescing, backoff and TCP DNS stacks, and pin admitted DNS tuples to their route. Registered own-UID test tuples use their test relay. Both exits can be probed individually; hold tests are 90 seconds, allow holding either exit in split mode and suppress DNS on the held route including replies from cache. Shared resolver traffic in Follow mode remains intentionally assigned to its configured exit. Existing global behavior remains selectable, with no plaintext or transport/provider/exit fallback. App-owned DoH remains outside managed resolver. No new root, firewall, or telephony policy. Actual peer outages still trigger whole-session recovery; not independent peer recovery or OS-level lockdown. More specific startup refusal codes and a bounded same-resolver connect retry included. Active/saved DNS strategy and countdown are visible; routing export includes DNS route strategy and shared/global exit. The on-device test must prove two active relay health/probe results, both browsers' actual public IP, strict unattributed counts and real DNS functionality; repeat 90-second hold with PCAP, Home streaming, migration and safe stop. LAN/multicast policy, system IPsec classification, full per-app inspector, opt-in blocked-domain diagnostics and crash lockdown remain separate work, not implemented by this batch.

## 0.26.0 — narrow root egress guard preview
Based on 0.25.1 (code 163). The user reported a paired PCAP/log test with successful split DNS, route isolation and recovery but direct privileged Android DNS and IPv6 traffic; no full-device leak guarantee. Old Batch F activation remains quarantined. New guard is default OFF, debug-only, explicitly selected and requires all-app capture plus root. It installs only after the authenticated bootstrap, verified peers and VPN interface establishment, so pre-establishment traffic is NOT guarded. Exact numeric WireGuard UDP endpoint plus app UID exceptions, exact TUN and loopback RETURN (never ACCEPT), narrow IPv4 broadcast DHCP and IPv6 local-control exemptions; direct TCP/UDP 53/853 and other non-TUN IPv6 traffic dropped. Local mDNS/SSDP optional; other IPv4 unchanged, including IPv4 IPsec. Carrier DNS and IPv6 connectivity may be affected. No broad direct IPv4 deny activation; policy model exists solely for offline test, runtime refuses it. No AFWall+ rule deletion or policy changes. Unique per-session chain/comment tags, persistent private journal committed before first mutation, preflight both families, anchor only after both complete, verify exact rules and order and first OUTPUT anchor, independent periodic audit/counters. On audit failure captured forwarding stops; firewall protection itself is unconfirmed, not atomically guaranteed against an external reload. On explicit Stop delete only exact journaled anchors/rules and empty chains, never flush; refusal retains journal. Unexpected teardown retains journal, rules may persist until offline recovery or reboot. Interface name reuse and reboot remain limitations; not full crash/boot lockdown. Existing selected-app/rootless mode remains unaffected when disabled. Device acceptance: first compare guard OFF baseline, then enable root guard in all-app Follow DNS, retain Private DNS OFF and AFWall+, test both browsers, Home, probes, inspect counters and PCAP, repeat isolation and migration only if stable, Stop and verify cleanup. Test carrier/Wi-Fi calling and discovery independently. Root grant, actual iptables match support, network recovery under guard, direct IPv4 bypass, IPv6 carrier compatibility, app inspector and whole-device protection remain unverified. Do not publish as stable or enable broad IPv4 guard before device results.
