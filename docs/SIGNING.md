# Wonhee Proxy — Permanent official release signing

Official package: com.yooshastan.wonheeproxy
Debug/test package: com.yooshastan.wonheeproxy.rootlab

## What the release certificate fixes

- All official signed APKs generated by the dedicated release workflow use a **single long-lived private signing key**.
- Once an official signed APK is installed, every subsequent official APK with the **same package ID, same signing identity and increasing versionCode** can normally upgrade in place using adb install -r, without clearing application data.
- The certificate is pinned by its **SHA-256 public fingerprint** in GitHub Actions. A regenerated or wrong private key is refused rather than distributed.
- The existing .rootlab test APK remains a separate package with an ephemeral CI debug certificate. **A release APK cannot upgrade this existing .rootlab APK in place**; these are intentionally separate installations.
- If an older installation of com.yooshastan.wonheeproxy exists with a different signature, the new release will NOT update it. Preserve its data and export/importable original WireGuard .conf files before removing it. Do not try to bypass the Android package signature verification.

## One-time private key generation: Fedora workstation only

**Never upload the signing keystore, raw base64 key, passwords or GitHub token into a chat, issue, commit or screenshot.** The official key should be created and kept under your own control. The app developer's workstation is the trust anchor.

1. Install Java keytool and the GitHub CLI if missing, authenticate GitHub CLI through its browser login:

   sudo dnf install java-21-openjdk-devel gh
   gh auth login
   gh auth status

2. Fetch the reviewed signing setup script into the local Wonhee checkout **without checking out another branch or overwriting worktree edits**:

   git fetch origin feature/persistent-official-signing-01524
   git show origin/feature/persistent-official-signing-01524:scripts/setup-wonhee-release-signing.sh > /tmp/setup-wonhee-release-signing.sh
   bash -n /tmp/setup-wonhee-release-signing.sh
   bash /tmp/setup-wonhee-release-signing.sh

3. The script:
   - Refuses overwriting or following a keystore symlink.
   - Creates ONE RSA-4096, PKCS#12 signing key (valid 10,000 days) at ~/.local/share/yooshastan/wonhee-signing/wonhee-release.p12 unless it already exists.
   - Shows only the **public certificate fingerprint**. Password input happens interactively on the maintainer's terminal.
   - Offers to set the five existing encrypted GitHub Actions repository secrets using the gh CLI; this requires repository permission.
   - Does not commit the keystore or write the password to source files.
   - Refuses generating a new key if GitHub signing secrets already exist but the original local keystore is unavailable.
   - Can re-upload an existing key only with explicit confirmation.

   **Do not use this setup script to replace an already-published release identity.** The public fingerprint is for identity verification. Save it in your private release records.

4. Back up the exact original .p12 keystore **and its password** securely in at least two controlled locations (e.g., encrypted backup + offline backup). Losing the signing key means you cannot release compatible updates to devices using it.

## Five required Actions secrets

The script can set these secrets; manual GitHub UI setup is also possible at Settings → Secrets and variables → Actions:

| Secret | Value |
| --- | --- |
| WONHEE_SIGNING_STORE_B64 | The single-line base64 encoding of the *existing original* .p12 keystore |
| WONHEE_SIGNING_STORE_PASSWORD | Keystore password |
| WONHEE_SIGNING_KEY_ALIAS | wonhee-release |
| WONHEE_SIGNING_KEY_PASSWORD | Same password for this PKCS#12 store/key |
| WONHEE_SIGNING_CERT_SHA256 | Public certificate SHA-256 fingerprint (64 hex characters, no separators) |

Do not print sensitive secret values to the terminal or GitHub logs. The secure setup script pipes them to gh secret set without command-line arguments.

## Locally signed 0.15.24 release candidate (before the main branch merges)

The public main branch still contains the older 0.8.6 release. For an official
0.15.24 APK *without merging hundreds of experimental commits into main*, a
trusted maintainer may build and sign locally on Fedora from the existing,
reviewed feature/persistent-official-signing-01524 branch.

Prerequisites: the private original .p12 keystore created by the one-time
setup, Java 17+ keytool, Go 1.23+ with checksum verification, Android SDK
platform android-36 and build-tools 35.0.0, and a clean Git worktree.

From the local clone:

    git fetch origin feature/persistent-official-signing-01524
    git switch feature/persistent-official-signing-01524
    git pull --ff-only origin feature/persistent-official-signing-01524
    bash -n scripts/build-wonhee-official-local.sh
    bash scripts/build-wonhee-official-local.sh

The local helper prompts for the keystore password without echoing it. It
builds the native ARM64 DNS helper and :app:assembleRelease, validates the APK
signature against the original local keystore's public SHA-256 certificate,
verifies Android application ID com.yooshastan.wonheeproxy, and writes:

    dist/wonhee-proxy-official-signed.apk
    dist/wonhee-proxy-official-signed.sha256

It does not upload a release, reinstall apps or change device networking.

Before installing: Safe stop the existing rootlab app, independently verify
no WN DNS firewall tags or priority-12500+ rules remain, confirm its WireGuard
links are DOWN, and separately inspect any loopback UDP 53535 listener. Leave
rootlab installed and its encrypted profiles untouched. Install the *official*
APK side by side only if the official package ID is not already occupied.

Local signing produces one candidate, not proof of future upgrade compatibility.
Once the official candidate is tested, produce a second build with an increased
versionCode signed by the SAME key, then verify an in-place adb install -r and
the persistence of its own official-app profiles and settings.

## Official signed APK build

The workflow is at .github/workflows/build.yml. The **signed-release** job is guarded:

- It runs ONLY for manual workflow_dispatch on refs/heads/main in the repository yooshastan/Wonhee-Proxy.
- Pull requests and feature-branch pushes produce disposable debug-signed .rootlab artifacts only; they never load production keys.
- Once the tested 0.15.24 feature and signing changes have been merged to main and GitHub repository secrets are set, open GitHub → Actions → Wonhee Proxy build → Run workflow → choose main.
- The job rebuilds the root DNS helper, builds a signed release APK, runs apksigner verify --verbose --print-certs, checks the pinned signer SHA-256, checks that the final application ID is exactly com.yooshastan.wonheeproxy, and publishes an APK and its SHA-256 checksum.
- The stable artifact name is wonhee-proxy-official-signed-release-apk. Never distribute an artifact from a failed signed job or one signed by the disposable debug key.

First publication requires a manual on-device install test and certificate verification, because CI checks cannot prove future Android in-place upgrades.

## First transition without losing the working lab

1. Before any install or uninstall, inspect both package IDs and installed certificate fingerprints with adb and apksigner. An existing older com.yooshastan.wonheeproxy package signed differently is a special migration case.
2. Stop the current .rootlab network stack safely, verify no WN_ DNS firewall tags, no reserved split priorities and no active tunnels. The local port 53535 listener should also be independently audited; don't kill an unverified process.
3. Leave .rootlab installed. Install the NEW official signed release side-by-side (if its package ID is unoccupied). It has separate application storage and cannot automatically access Android-Keystore-sealed .rootlab profiles.
4. Import the original .conf profiles and trusted blocklists into the official app using your own secure backups. Do not paste WireGuard private keys into logs or chat.
5. Verify start, safe stop, Home split routing, Internet egress, DNS relay and imported tracker filtering in the official app. Do not operate both .rootlab and official root stacks simultaneously.
6. Produce a second signed official APK with a higher versionCode and the same private key. Run adb install -r on the official package; check that its stored profiles and settings survive. Only then consider the official track ready for general use.
7. Keep .rootlab until the official migration has been validated. Its CI debug APK still uses an ephemeral signature and cannot be replaced by official signing via adb install -r.

## Security note

A PKCS#12 keystore is sensitive. Do not store it in the GitHub repository, under Android /sdcard, in an unencrypted cloud folder or in logs. Repository Actions secrets permit the guarded main workflow to use the key for signing but cannot protect against every compromise of repository administrator privileges; restrict who can modify main and workflow files.

The signing setup does NOT auto-publish a new release; the maintainer must generate the key, configure secrets and manually dispatch signed-release after the feature changes reach main.
