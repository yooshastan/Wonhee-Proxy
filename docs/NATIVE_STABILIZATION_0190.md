# 0.19.0 DNS stabilization
Baseline 0.18.0 commit 2f2b5dc9976ccb01c22efe4852728b97b10bb78a: user verified Moka and browser Navidrome, Kroger and McDonald's, 97% Turtlecute and no observed IP leak. Device log: 2213 DNS requests, 1926 blocked, 287 authenticated, zero DNS failures, overflow, queue drops or foreign replies; 5208 of 5216 policy drops associated with ended relay ports. No proof of universal leak prevention.
Retain same debug package, versionCode 151, single launcher and immutable routing admission. Reuse authenticated in-tunnel DoT connections with up to four concurrent workers and four idle connections, bounded 30s idle expiry and 128 exchanges per connection. One same-provider/same-role fresh TLS retry only after reused connection I/O failure; no plaintext or direct fallback. Registered socket ownership remains required; late teardown packets still rejected. Positive A/AAAA-only per-session cache, 512-entry LRU, exact normalized question excluding transaction ID, conservative answer-only owner and type checks, TTL capped at 120s and aged down, no negative/alias/truncated cache, local HOSTS precedence; no disk or domain logs. Added cache/TLS lifecycle counters. Stop closes all known sockets and clears in-memory cache. Device validation pending. No TCP DNS fallback, DoQ/DoH3, unattended recovery, process-death kill switch or signed production release in this build; these require additional validation and design.
